# tors v0.1.0 — design (approved 2026-09-05)

**tors** is a GIL-free text normalization library for CPython, backed by Rust. It exists
because a class of CPython work — single GIL-held C calls over unbounded strings
(`re.sub`, `unicodedata.normalize`, `str.replace`) — stalls the event loop wherever it
runs, and `asyncio.to_thread` cannot bound it. cennan (helix's semantic-indexing service)
carries a hand-rolled seam-safe chunking workaround for exactly this class
(`_sub_chunked`, D33 clause 4); tors replaces that tier natively: the whole transform in
one `py.detach` pass.

## Decisions (locked with the owner)

| # | Decision |
|---|---|
| D1 | v0.1 API surface: `normalize` + `finalize` only. |
| D2 | "End to end" includes the cennan swap-in (delete the chunking machinery) in this effort. |
| D3 | Consumption order: validate via pinned git rev in cennan first, then publish PyPI wheels and flip cennan to the wheel. Never publish an API not yet consumed for real. |
| D4 | Chunking (chonkie-class) is NOT in v0.1: cennan's chunkers are GIL-*yielding* (D33 measured ~15ms worst gap in a thread; pinned green in CI), so the case there is throughput, not GIL-release — a separately measured v0.2 decision. |
| D5 | Distribution: manylinux x86_64 + aarch64 wheels + sdist via cibuildwheel, PyPI trusted publishing, release-please + conventional commits. mac/win wheels deferred (no consumer; sdist builds work). |

## API contract (frozen for v0.1)

```python
tors.normalize(text: str) -> str
tors.finalize(text: str) -> tuple[str, str]  # (normalized, sha256-hex-of-utf8)
```

- Pipeline (both): NFC → fold CRLF/CR → drop `[ \t]+` runs before a newline → collapse
  `\n{3,}` to `\n\n` → `str.strip()` (Python's exact whitespace set, incl. 0x1c–0x1f).
  `finalize` additionally returns lowercase-hex SHA-256 of the result's UTF-8 bytes —
  byte-identical to `hashlib.sha256(normalized.encode("utf-8")).hexdigest()`.
- GIL: released for the whole native pass (`py.detach`). The ONLY GIL-held part is
  pyo3's return marshalling (Rust `String` → `PyString`, O(output): measured and
  documented in the README; callers that care keep a `to_thread` wrap — cennan does).
- Argument extraction is a zero-copy borrow; no allocation beyond the output.
- Unicode tables: tors's own (`unicode-normalization` crate). **Headline guarantee: same
  input → same output/hash on every supported interpreter (3.10–3.14)** — a property
  CPython's per-version `unicodedata` cannot promise; this is what makes tors safe for
  hash-gated dedupe. Per-version parity with each interpreter's own `unicodedata` is
  pinned by the oracle tests running on every matrix leg.

## Correctness proofs (test suite)

1. Existing suites stay: behavioral cases, exhaustive ≤4 over the trigger alphabet,
   hypothesis ×2 (vs a pure-Python reference oracle using the *running* interpreter's
   `unicodedata`), seeded-random.
2. NEW exhaustive NFC sweep: every canonically-decomposable codepoint —
   `tors.normalize(NFD(c)) == unicodedata.normalize("NFC", NFD(c))` — plus Hangul
   syllable samples. Runs per matrix leg → pins parity with every Python's tables.
3. NEW strip-set parity: for every `chr(c)` where `chr(c).isspace()`,
   `normalize(ws + "x") == normalize("x" + ws) == "x"`; negative pins for non-whitespace
   look-alikes (e.g. U+200B) proving they are preserved.
4. NEW not-NFKC pin: compat ligatures (U+FB01) must NOT compose.
5. NEW finalize consistency property (hypothesis):
   `finalize(t) == (normalize(t), sha256(normalize(t).encode()).hexdigest())`.

## Performance proofs ("provably performant")

1. **GIL proof as a CI test** (the claim, tested, not asserted): worst-heartbeat-gap
   method (10ms ping; ratio-based multi-sample assertion, load-robust on 2-vCPU
   runners). `finalize` at 12MB and ≥32MB corpora: worst gap must sit in the
   marshalling band (measure first, then budget with ≥5× margin below the CPython
   pipeline's 100ms–1s). A size- pair proves the gap is size-independent.
2. Wall-time: tors beats the pure-Python reference pipeline at 1KB/1MB/12MB (prose,
   decomposed, CRLF corpora) — a tolerant CI assertion (same-runner comparison) plus
   full numbers recorded in the README from a quiet local run with methodology.
3. Criterion benches (Rust side): `normalize`/`finalize` at 1KB/1MB/12MB/100MB with an
   in-repo corpus generator; `cargo bench` locally, `--no-run` in CI; guards against
   tors's own regressions across versions.

## Engineering discipline (no broken windows)

- CI: every action SHA-pinned (no `@v4` tags), `cargo fmt --check`, `cargo clippy --
  -D warnings`, `cargo test --no-default-features` (one leg), uv sync + pytest matrix
  3.10–3.14, wheel build job (maturin, no publish until M4).
- `pyo3/abi3-py310` → one manylinux wheel per arch covers the matrix.
- README: contract, guarantees, measured numbers + methodology + machine disclosure,
  usage, dev setup (`uv sync`, `maturin develop`). CHANGELOG via release-please.
- Cargo.lock committed; MSRV 1.90; MIT.

## cennan swap-in (M3, after tors validates)

- Consume via `[tool.uv.sources]` git rev (taskq-py pattern); flip to the PyPI wheel at
  publish. Dependency floor+cap `<0.2`.
- `normalize_text` → `tors.normalize`; `finalize_text` → `asyncio.to_thread(tors.finalize)`
  (kept for the return-marshalling residual; documented). DELETE `_sub_chunked`,
  `_SUB_CHUNK_CHARS`, `_WS` machinery and the 7 seam-test classes; retarget the golden
  trio (old-literal oracle, boundary pins, NFC pin); loop-safety test re-measured
  (expect ~marshalling-band gap vs 0.5 budget) + NEW decomposed-corpus variant (the F1
  gap); D33 clause-4 correction + new D36 entry; full unit lanes 3.12/3.13, e2e
  extraction path, `make ci`.
